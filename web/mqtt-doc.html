CMT-IPAS Industrial Audio Gateway - Channel Switching via MQTT

🔌 Connection Settings

MQTT Broker Information

Host: 127.0.0.1 (or your server IP)

Port: 1883 (TCP) / 8083 (WebSocket)

Username: Your device username

Password: Your device password

📋 Request Channel List

Get list of available channels that the user can access and their current location.

cmt/channels/list/{username} PUBLISH

Description: Publish to this topic to request the list of channels available for the specified user. Note: The server will only return channels the user has permission to enter.

Payload: The username string (plain text) or JSON containing username.

phichet_2

Example: cmt/channels/list/phichet_2

cmt/user/channel/list/{username} SUBSCRIBE

Description: Subscribe to this topic to receive the channel list response and current location.

Response Payload:

{
  "username": "phichet_2",
  "current_channel": {
    "id": 0,
    "name": "Root (Lobby)"
  },
  "channels": [
    {
      "id": 1,
      "name": "CMT-TEST01",
      "is_private": false,
      "has_invitation": false,
      "can_access": true
    },
    {
      "id": 2,
      "name": "CMT-TEST02",
      "is_private": true,
      "has_invitation": true,
      "can_access": true
    }
  ]
}

📝 Usage Steps

1

Subscribe to cmt/user/channel/list/{username}

2

Publish to cmt/channels/list/{username}

3

Receive channel list and current location on the response topic

🔄 Move to Channel

Commands to switch between channels via MQTT.

cmt/user/channel/move/{username} PUBLISH ★ RECOMMENDED FOR CLIENTS

Description: Move yourself to a target channel securely. No session_id required.

Auto-Refresh: The server will automatically send an updated channel list after a successful move.

Request Payload:

{
  "channel_id": 1
}

(Or just send the number 1 as plain text payload)

cmt/channels/move PUBLISH ⚠️ ADMIN ONLY

Description: Administrative move command. Requires specific session identification.

Request Payload:

{
  "username": "user1",
  "session_id": 123,
  "channel_id": 2
}

📊 Payload Fields Reference

Field Type Description
username String Username of the user
current_channel Object Contains id and name of user's current channel
channel_id Number ID of the target channel for move requests
channels Array List of accessible channels
can_access Boolean Always true in the filtered list

💡 Complete Example

Scenario: User "phichet_2" wants to switch to CMT-TEST01

Step 1: Get Status & List

Subscribe to: cmt/user/channel/list/phichet_2

Publish to: cmt/channels/list/phichet_2

Step 2: Process Response

Server returns current channel (e.g., Root) and list of accessible channels (IDs 1, 2).

Step 3: Move to Channel 1

Publish to: cmt/user/channel/move/phichet_2

Payload: {"channel_id": 1}

⚠️ Important Notes

Security

The new cmt/user/channel/move/{username} topic ensures that users can only move their own sessions to channels they have explicit permission to enter.

QoS Level

All MQTT operations use QoS 0 (At Most Once) for performance. If guaranteed delivery is needed, the client should implement its own acknowledgment logic by listening for its own position changes.
